Hooks are functions Dyrected runs at defined points in a document's lifecycle. They are the right place to validate input, derive values, enforce invariants, and trigger side effects such as cache revalidation or notifications.

Every hook runs on the server, so they are safe to use for logic you never want a client to bypass.

## Where hooks run

Hooks are configured per collection, per global, and per field. Collection and global hooks share the same lifecycle shape:

- `beforeRead` runs before the database is queried.
- `afterRead` runs on each document after it is fetched.
- `beforeChange` runs before a create or update is written.
- `afterChange` runs after a write is committed, for side effects.
- `beforeDelete` and `afterDelete` bracket deletions (collections only).

```ts
import { defineCollection } from '@dyrected/core'

export const Posts = defineCollection({
  slug: 'posts',
  fields: [{ name: 'title', type: 'text', label: 'Title' }],
  hooks: {
    beforeChange: [({ data }) => ({ ...data, slug: slugify(data.title) })],
    afterChange: [({ doc }) => revalidateTag(`post-${doc.id}`)],
  },
})
```

Hooks in an array run in order, and each hook's return value feeds the next. Throwing inside a `before*` hook aborts the operation; `after*` hooks are for side effects and their errors are isolated so a failed webhook never turns a successful write into a `500`.

## Field hooks

Field-level hooks let you transform a single field's value as it is read or written, without touching the rest of the document. They are useful for encryption, formatting, and computed field values.

## AuthenticatedUser

Base shape of an authenticated user as decoded from the JWT.

The actual shape will include every field on your auth collection — this
interface only guarantees the properties that Dyrected always stamps on the
token. Extend it in your own codebase for stronger typing:

```ts
export interface AuthenticatedUser {
  /** The user's document ID in the database. */
  sub: string;
  /** The user's email address. */
  email?: string;
  /** Slug of the collection this user was authenticated against. */
  collection: string;
  /** Array of role strings, if your auth collection has a `roles` field. */
  roles?: string[];
  /** Any additional fields from the auth collection document. */
  [key: string]: unknown;
}
```

| Option | Description |
| --- | --- |
| <code>sub</code> (required) | The user's document ID in the database. |
| <code>email</code> (optional) | The user's email address. |
| <code>collection</code> (required) | Slug of the collection this user was authenticated against. |
| <code>roles</code> (optional) | Array of role strings, if your auth collection has a &#96;roles&#96; field. |

## HookRequestContext

Minimum HTTP request context passed to every server-side hook and resolver.

The full Web Standard `Request` is available as `raw` when you need it, but
most hooks only need `query` (URL search parameters).

```ts
export interface HookRequestContext {
  /** Parsed URL query-string parameters, e.g. `{ page: '2', search: 'hello' }`. */
  query: Record<string, string>;
  /** Incoming HTTP headers, lowercased. */
  headers: Record<string, string>;
  /** The raw Web Standard `Request` object. Useful for streaming or advanced header inspection. */
  raw?: Request;
}
```

| <code>headers</code> (required) | Incoming HTTP headers, lowercased. |
