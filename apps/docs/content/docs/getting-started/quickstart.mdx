## Prerequisites

Before you start, ensure you have:

- [Node.js 22+](https://nodejs.org) installed
- A package manager ([pnpm](https://pnpm.io) recommended, or `npm`/`yarn`/`bun`)
- Basic familiarity with your chosen framework (Next.js or Nuxt.js)

---

## First choose your setup

Dyrected has three choices that are easy to blur together:

- **Backend**: Dyrected Cloud backend or self-hosted backend
- **Admin location**: hosted admin at `app.dyrected.com` or embedded admin in your app at `/admin`
- **Update ownership**: hosted admin updates automatically; embedded admin ships with your app deploys; self-hosted backend upgrades are yours to manage

If you want the shortest path with the least maintenance, start with a Cloud backend and hosted admin. If you want a white-label handoff, keep the Cloud backend and embed the admin into your app.

---

## Cloud Backend

This path uses the **Dyrected Cloud backend**. Your content API, database, storage, and auth live on Dyrected's servers. You can then choose either the hosted admin at `app.dyrected.com` or an embedded admin route inside your own app.

**Prerequisites & assumptions**

- You already have a website or app repo, open in an AI coding tool such as Lovable, Bolt, v0, Cursor, Replit, or Windsurf.
- You're willing to create a free [Dyrected Cloud](https://app.dyrected.com) account — no Postgres, S3, or server to provision.
- No prior Dyrected knowledge assumed — the setup prompt below teaches your AI builder everything it needs.

### Easiest: paste the setup prompt

Instead of writing integration code yourself, copy a setup prompt from Dyrected and paste it into your AI builder. The AI handles the entire integration in stages — including running `npx dyrected init` and `npx dyrected sync:schema` for you, so your Cloud database is ready without you touching the CLI. This is the recommended path over setting things up by hand.

**Before you start**

- Open the project in the AI builder that owns the website code.
- [Create a Dyrected site](https://app.dyrected.com) and keep the site settings open. You will need the Site ID, Site API key, and Base URL — the prompt tells the AI when to ask for them.

<Steps>
<Step>
### Copy the setup prompt

Open your Dyrected site and go to **Setup**. Copy the setup prompt — your credentials are pre-filled when you copy from inside the admin panel. Or copy the base prompt here:

<CopyPromptButton />
</Step>
<Step>
### Paste the prompt into your AI builder

Paste the prompt into the same AI builder that can read and edit the website code. The AI will respond with a plain-language checklist of everything on the website a client could reasonably want to change.

</Step>
<Step>
### Approve the checklist

Read the checklist top to bottom. If something is missing or unnecessary, say what to add, remove, or change. Say **"approved"** when it looks right.

</Step>
<Step>
### Give the AI your Dyrected details

The prompt makes the AI wait until the install stage before asking for credentials. When it asks, provide your Site ID, Site API key, and Base URL.

</Step>
<Step>
### Test one real edit

Open Dyrected and change a piece of content you can easily recognize — a heading, an image, or a list item. Confirm the change appears on the website and the design still looks right.

</Step>
<Step>
### Choose how the client logs in

- Use the **hosted admin** if you want automatic admin updates and the lowest maintenance
- Use the **embedded admin** if you want the client to work inside your own domain at `/admin`
  </Step>
<Step>

### Invite the client

Invite the client only after one Dyrected edit appears on the live website.

</Step>
</Steps>

## Self-hosted Next.js

This path uses a **self-hosted backend** inside your Next.js app. Your admin can still live at `/admin`, but backend upgrades and infrastructure remain your responsibility.

**Prerequisites & assumptions**

- [Node.js 22+](https://nodejs.org) and a package manager (pnpm recommended).
- An existing Next.js app using the **App Router** (`@dyrected/next` doesn't support the Pages Router — add an `app/` directory first if you don't have one).
- Comfort running one terminal command and editing an `.env` file. No prior Dyrected knowledge assumed beyond that.

### Easiest: paste the setup prompt

Instead of wiring up config, collections, and the admin route by hand, copy the Dyrected setup prompt and paste it into an AI coding tool that has access to this repo (Claude Code, Cursor, Windsurf, etc.). It will run `npx dyrected init` for you, model your existing content as collections and globals, mount the admin, and seed initial data — all in guided stages you approve one at a time.

<CopyPromptButton mode="self-hosted" />

When it reaches the install stage, it will ask for your **Site API key** and **Base URL** — self-hosted projects don't have a Site ID, so tell the AI that field doesn't apply.

### Manual setup

If you'd rather do this yourself, the CLI is the safest way to install — it detects your project layout and writes files in the right place, instead of you hand-assembling config that can drift from what the installed package actually supports.

<Steps>
<Step>
### Install with the CLI

```bash
npx dyrected init
```

The CLI auto-detects your framework from `package.json`. Choose **Quick Setup** for SQLite + local file storage during local development. It will:

- Install `@dyrected/core`, `@dyrected/next`, `@dyrected/db-sqlite`, and `@dyrected/storage-local`.
- Create a `dyrected.config.ts`.
- Detect your App Router layout, including optional `src/` directory, and write files in the right place.
- Mount the API route at `app/dyrected/[...route]/route.ts` or `src/app/dyrected/[...route]/route.ts`.
- Mount the Admin UI at the path you choose during setup, defaulting to `app/admin/page.tsx` or `src/app/admin/page.tsx`.
- Generate `instrumentation.ts` so your server logs the admin and API URLs on startup.
- Generate a `.env.example`.
  </Step>
<Step>

### Define your config: collections and globals

Open `dyrected.config.ts` and describe your content model — see [Collections and Globals](/docs/concepts/collections-and-globals). Use **collections** for repeatable content (blog posts, products) and **globals** for shared site-wide settings (nav, footer, SEO defaults).

</Step>
<Step>
### Run it and confirm `/admin` loads

1. Copy `.env.example` to `.env` and fill in the values.
2. Run `pnpm dev`.
3. Your database schema is synced automatically on startup — no manual CLI sync required for self-hosted projects.
4. The admin URL is printed to the console on startup — open it and confirm you can log in and see your collections.
   </Step>
<Step>

### Seed initial data

Add `initialData` to a collection or global in `dyrected.config.ts` so it isn't empty on first load — see [Seeding initial data](/docs/concepts/schema#seeding-initial-data).

</Step>
<Step>
### Integrate with your website

Fetch content into your pages using the SDK or REST API — see [Next.js integration](/docs/integrations/nextjs).

</Step>
</Steps>
