## Prerequisites

Before you start, ensure you have:

- [Node.js 22+](https://nodejs.org) installed
- A package manager ([pnpm](https://pnpm.io) recommended, or `npm`/`yarn`/`bun`)
- Basic familiarity with your chosen framework (Next.js or Nuxt.js)

## First choose your setup

Dyrected has three choices that are easy to blur together:

- **Backend**: Dyrected Cloud backend or self-hosted backend
- **Admin location**: hosted admin at `app.dyrected.com` or embedded admin in your app at `/admin`
- **Update ownership**: hosted admin updates automatically; embedded admin ships with your app deploys; self-hosted backend upgrades are yours to manage

If you want the shortest path with the least maintenance, start with a Cloud backend and hosted admin. If you want a white-label handoff, keep the Cloud backend and embed the admin into your app.

## Cloud Backend

This path uses the **Dyrected Cloud backend**. Your content API, database, storage, and auth live on Dyrected's servers. You can then choose either the hosted admin at `app.dyrected.com` or an embedded admin route inside your own app.

Dyrected Cloud is designed for websites built with AI tools such as Lovable, Bolt, v0, Cursor, Replit, or Windsurf. Instead of writing integration code yourself, you copy a setup prompt from Dyrected and paste it into your AI builder. The AI handles the entire integration in stages.

**Before you start**

- Open the project in the AI builder that owns the website code.
- [Create a Dyrected site](https://app.dyrected.com) and keep the site settings open. You will need the Site ID, Site API key, and Base URL — the prompt tells the AI when to ask for them.

**1. Copy the setup prompt**

Open your Dyrected site and go to **Setup**. Copy the setup prompt — your credentials are pre-filled when you copy from inside the admin panel. Or copy the base prompt here:

<CopyPromptButton />

**2. Paste the prompt into your AI builder**

Paste the prompt into the same AI builder that can read and edit the website code. The AI will respond with a plain-language checklist of everything on the website a client could reasonably want to change.

**3. Approve the checklist**

Read the checklist top to bottom. If something is missing or unnecessary, say what to add, remove, or change. Say **"approved"** when it looks right.

**4. Give the AI your Dyrected details**

The prompt makes the AI wait until the install stage before asking for credentials. When it asks, provide your Site ID, Site API key, and Base URL.

**5. Test one real edit**

Open Dyrected and change a piece of content you can easily recognize — a heading, an image, or a list item. Confirm the change appears on the website and the design still looks right.

**6. Choose how the client logs in**

- Use the **hosted admin** if you want automatic admin updates and the lowest maintenance
- Use the **embedded admin** if you want the client to work inside your own domain at `/admin`

**7. Invite the client**

Invite the client only after one Dyrected edit appears on the live website.

## Self-hosted Next.js

This path uses a **self-hosted backend** inside your Next.js app. Your admin can still live at `/admin`, but backend upgrades and infrastructure remain your responsibility.

**1. Initialize**

```bash
npx @dyrected/cli init
```

The CLI auto-detects your framework from `package.json`. Choose **Quick Setup** for SQLite + local file storage during local development. It will:

- Install `@dyrected/core`, `@dyrected/next`, `@dyrected/db-sqlite`, and `@dyrected/storage-local`.
- Create a `dyrected.config.ts`.
- Detect your App Router layout, including optional `src/` directory, and write files in the right place.
- Mount the API route at `app/dyrected/[...route]/route.ts` or `src/app/dyrected/[...route]/route.ts`.
- Mount the Admin UI at the path you choose during setup, defaulting to `app/admin/page.tsx` or `src/app/admin/page.tsx`.
- Generate `instrumentation.ts` so your server logs the admin and API URLs on startup.
- Generate a `.env.example`.

> **Note:** `@dyrected/next` requires the Next.js App Router. If your app only has the Pages Router, add an `app/` directory before running init.

**2. Configure and Run**

1. Copy `.env.example` to `.env` and fill in the values.
2. Run `pnpm dev`.
3. The admin URL is printed to the console on startup — open it to start managing content.

> **Note:** Your database schema is synced automatically on startup. No manual CLI sync is required for self-hosted projects.

## Self-hosted Nuxt.js

This path uses a **self-hosted backend** inside your Nuxt.js app. Your admin can still live at `/admin`, but backend upgrades and infrastructure remain your responsibility.

**1. Initialize**

```bash
npx @dyrected/cli init
```

The CLI auto-detects your framework from `package.json`. Choose **Quick Setup** for SQLite + local file storage during local development. It will:

- Install `@dyrected/core`, `@dyrected/nuxt`, `@dyrected/db-sqlite`, and `@dyrected/storage-local`, then create `dyrected.config.ts`.
- Detect whether you use an `app/` directory and write the admin page to the path you choose during setup, defaulting to `app/pages/admin/index.vue` or `pages/admin/index.vue`.
- Automatically add `@dyrected/nuxt` to `modules` in your `nuxt.config.ts`.
- Generate a `.env.example`.

**2. Configure and Run**

1. Copy `.env.example` to `.env` and configure your secrets.
2. Run `pnpm dev`.
3. The Dyrected admin and API URLs are printed to the console when the dev server starts — open the admin URL to start managing content.

> **Note:** Your database schema is synced automatically on startup. No manual CLI sync is required for self-hosted projects.
