`@dyrected/sdk` is a framework-agnostic TypeScript client for the Dyrected REST API. It works in Next.js, Nuxt.js, SvelteKit, plain Node.js, and browser environments.

> [!NOTE]
> **Scope Statement:** The SDK covers document CRUD and relationship traversal via `depth`. It does not expose count, aggregate, or complex join queries. For those, write an API route and query the database directly using your database adapter.

---

## Installation

```bash
pnpm add @dyrected/sdk
# or
npm install @dyrected/sdk
```

---

## Creating a Client

```ts
import { createClient } from '@dyrected/sdk'

const client = createClient({
  baseUrl: 'https://your-site.com/api',  // Your Dyrected API base URL
  apiKey: process.env.DYRECTED_API_KEY,  // Site API Key
  siteId: process.env.DYRECTED_SITE_ID,  // Required in Cloud mode
})
```

### Options

| Option | Type | Required | Description |
|---|---|---|---|
| `baseUrl` | `string` | ✅ | Base URL of your Dyrected instance |
| `apiKey` | `string` | | Site API Key. Sent as `x-api-key` header. |
| `siteId` | `string` | | Site ID. Sent as `x-site-id` header. Required in Cloud mode. |
| `defaultDepth` | `number` | | Default relationship population depth (default: `1`) |
| `fetch` | `typeof fetch` | | Custom `fetch` implementation (e.g., for Node 18 polyfills) |

## Collection Methods

All collection methods are accessed via `client.collection(slug)`.

### `.find(options?)`

> [!TIP]
> **Looking for a single document by ID?**  
> Use `client.collection('posts').findOne(id)` instead of `find({ where: { id: { equals: id } }, limit: 1 })`. It returns the document directly, rather than a paginated result.

Returns a paginated list of documents.

```ts
const result = await client.collection('posts').find({
  limit: 10,
  page: 1,
  sort: '-createdAt',
  depth: 1,
  where: {
    status: { equals: 'published' },
  },
})

// result.docs: Post[]
// result.total: number
// result.totalPages: number
// result.hasNextPage: boolean
```

When `where` is passed as an object, the SDK serializes it for the REST API automatically. Boolean values such as `{ featured: { equals: true } }` are preserved and parsed correctly by the server.

#### Where Operators

Dyrected supports a rich set of operators for filtering your data. These work seamlessly across all database adapters.

| Operator | Description | Example |
|---|---|---|
| `equals` | Strict equality | `{ status: { equals: 'published' } }` |
| `not_equals` | Inequality | `{ status: { not_equals: 'draft' } }` |
| `in` | Value exists in array | `{ category: { in: ['news', 'events'] } }` |
| `not_in` | Value does not exist in array | `{ category: { not_in: ['spam'] } }` |
| `exists` | Field is present (or not) | `{ publishedAt: { exists: true } }` |
| `gt` | Numeric/date greater than | `{ price: { gt: 100 } }` |
| `gte` | Numeric/date greater than or equal | `{ age: { gte: 18 } }` |
| `lt` | Numeric/date less than | `{ price: { lt: 500 } }` |
| `lte` | Numeric/date less than or equal | `{ age: { lte: 65 } }` |
| `contains` | Case-insensitive contains | `{ title: { contains: 'typescript' } }` |
| `starts_with` | Starts with value | `{ slug: { starts_with: 'post-' } }` |

Multiple fields in the same `where` object are combined with `AND`.

### Relationship Depth

The `depth` parameter controls how many levels of relationships are automatically "hydrated" (populated) in a single request.

- **`depth: 0`**: Only returns the ID of the related document.
- **`depth: 1`** (Default): Populates the first level of relationships with their full document data.
- **`depth: 2+`**: Recursively populates nested relationships.

> [!TIP]
> Use `depth: 0` for high-performance listing pages where you only need IDs, and higher depth for detail pages where you need full author/category info.

---

### `.findOne(id, options?)`

Fetch a single document by ID.

```ts
const post = await client.collection('posts').findOne('abc123', { depth: 2 })
```

---

### `.create(data)`

Create a new document.

```ts
const post = await client.collection('posts').create({
  title: 'My New Post',
  status: 'draft',
})
```

---

### `.update(id, data)`

Partially update a document. Only the fields you pass are changed.

```ts
const updated = await client.collection('posts').update('abc123', {
  status: 'published',
  publishedAt: new Date().toISOString(),
})
```

---

### `.delete(id)`

Delete a document by ID.

```ts
await client.collection('posts').delete('abc123')
```

---

### `.upload(file, data?)`

Upload a file to an upload collection. Accepts a `File` or `Blob` (browser).

```ts
// Browser — File from <input type="file">
const mediaDoc = await client.collection('media').upload(file, {
  alt: 'A mountain landscape',
})

// Blob from fetch or canvas
const blob = await fetch('/some-image.jpg').then(r => r.blob())
const mediaDoc = await client.collection('media').upload(blob, {
  alt: 'Fetched image',
})
```

---

### `.transition(id, transitionName, options?)`

Perform a workflow transition on a document. Returns the updated document.

```ts
const updated = await client.collection('posts').transition('abc123', 'publish', {
  expectedRevision: 2, // Concurrency guard matching doc._workflow.revision
  comment: 'Approving for publication.' // Required if requireComment: true
})
```

---

### `.workflowHistory(id, options?)`

Fetch the workflow transition history for a document.

```ts
const history = await client.collection('posts').workflowHistory('abc123', {
  limit: 20
})

// history.docs: WorkflowHistoryEntry[]
// history.docs[0].transition: string ('submit', 'publish', etc.)
// history.docs[0].comment: string | null
```

## Global Methods

Access globals via `client.global(slug)`.

### `.get(options?)`

```ts
const settings = await client.global('site-settings').get({ depth: 1 })
```

### `.update(data)`

```ts
await client.global('site-settings').update({
  maintenanceMode: true,
})
```

## Authentication

Authentication is performed on auth-enabled collections.

### `.login(email, password)`

```ts
const { token, user } = await client.collection('users').login('admin@example.com', 'password')

// Attach token to the client for subsequent requests
client.setToken(token)
```

### `.logout()`

```ts
await client.collection('users').logout()
client.clearToken()
```

### `.me()`

Returns the currently authenticated user document.

```ts
const user = await client.collection('users').me()
```

### `.refreshToken()`

```ts
const { token } = await client.collection('users').refreshToken()
client.setToken(token)
```

### `.invite(email)`

Send an invitation to an email address (requires an authenticated token set via `setToken`).

```ts
await client.collection('users').invite('newuser@example.com')
```

### `.acceptInvite(token, password, extraFields?)`

Create an account from an invite token. Returns `{ token, user }` — the user is logged in immediately.

```ts
const { token, user } = await client.collection('users').acceptInvite(inviteToken, 'my-password', {
  name: 'Jane Doe',
})
client.setToken(token)
```

---

### `.setToken(token)` / `.clearToken()`

Manually manage the authentication header.

```ts
client.setToken(token)
client.clearToken()
```

## Schema Methods

### `.getSchemas()`

Returns the full schema definition for all collections and globals.

```ts
const schemas = await client.getSchemas()
// schemas.collections: CollectionSchema[]
// schemas.globals: GlobalSchema[]
```

## Preference Methods

Preferences store small user-specific Admin UI choices, such as visible table columns. They are keyed strings and return JSON-compatible values.

### `.getPreference(key)`

```ts
const pref = await client.getPreference<string[]>('columns:pages')
// pref.value: string[] | null
```

### `.setPreference(key, value)`

```ts
await client.setPreference('columns:pages', ['title', 'slug', 'updatedAt'])
```

The Admin UI falls back to local storage when server preferences are unavailable.

## TypeScript Generics

The SDK is fully typed. Pass your document type as a generic for type-safe responses:

```ts
interface Post {
  id: string
  title: string
  status: 'draft' | 'published'
  author: string | Author  // string at depth=0, Author at depth>=1
  createdAt: string
}

const result = await client.collection<Post>('posts').find({ depth: 1 })
// result.docs is Post[]
```

## Error Handling

The SDK throws a `DyrectedError` on non-2xx responses.

```ts
import { DyrectedError } from '@dyrected/sdk'

try {
  const post = await client.collection('posts').findOne('invalid-id')
} catch (err) {
  if (err instanceof DyrectedError) {
    console.log(err.statusCode) // 404
    console.log(err.message)
    console.log(err.errors)     // validation error array (on 400)
  }
}
```

## Next.js Usage

```ts
// app/blog/[slug]/page.tsx
import { createClient } from '@dyrected/sdk'

const client = createClient({
  baseUrl: process.env.DYRECTED_URL!,
  apiKey: process.env.DYRECTED_API_KEY!,
})

export default async function BlogPost({ params }: { params: { slug: string } }) {
  const { docs } = await client.collection('posts').find({
    where: { slug: { equals: params.slug } },
    depth: 1,
  })
  const post = docs[0]
  if (!post) notFound()

  return <article>{post.title}</article>
}
```
