---
title: Field Types
description: Complete reference for every field type available in Dyrected, including all properties, validation rules, and Admin UI behaviour.
---

Every field in a collection or global is defined by a `Field` object. All fields share a common set of base properties, and individual types add their own.

---

## Base Properties (All Fields)

| Property | Type | Required | Description |
|---|---|---|---|
| `name` | `string` | ✅ (omit for `row`) | The key used in the database and JSON responses. Use camelCase. Layout fields (`row`) do not require a name since they produce no database column. |
| `type` | `FieldType` | ✅ | The field type (see below). |
| `label` | `string` | | Display name in the Admin UI. Defaults to a title-cased version of `name`. |
| `required` | `boolean` | | If `true`, the field must have a non-empty value. Enforced on both client and server. |
| `unique` | `boolean` | | If `true`, the database adapter enforces a unique constraint for this field across the collection. |
| `defaultValue` | `any` | | The initial value for new documents. Type must match the field type. |
| `admin` | `object` | | UI-specific options. See [Admin Field Options](#admin-field-options). |
| `access` | `object` | | Field-level read/update permissions. See [Field Access](#field-access). |
| `hooks` | `object` | | Field-level lifecycle hooks. See [Field Hooks](#field-hooks). |

> [!NOTE]
> **Admin UI Indicators:** Fields marked as `required: true` will display a red asterisk (`*`) next to their label. Fields marked as `unique: true` will display a blue "Unique" badge to alert editors about data constraints.

## Text Fields

### `text`

A single-line text input.

```ts
{
  name: 'title',
  type: 'text',
  required: true,
  unique: true,
  admin: {
    placeholder: 'Enter a title...',
    description: 'Used as the page heading and browser tab title.',
  }
}
```

- **Stored as:** `VARCHAR` (SQL) / `string` (MongoDB)
- **API returns:** `string`
- **Admin UI:** `<input type="text" />` with optional live character/word limit counters and warnings

#### Size & Word Limits

You can restrict the length of `text` and `textarea` fields using character or word constraints. The Admin UI renders an interactive limit indicator at the bottom-right of the input:
- **Amber Warning**: Renders when the length reaches 80% or more of the configured limit.
- **Red/Destructive Warning**: Renders bold when the length reaches or exceeds 100% of the limit.

| Property | Type | Scope | Description |
|---|---|---|---|
| `maxLength` | `number` | Field / `admin` / `validate` | Maximum number of characters allowed. |
| `maxWords` | `number` | Field / `admin` | Maximum number of words allowed. |

```ts
{
  name: 'excerpt',
  type: 'textarea',
  maxLength: 160, // Shows character count: Amber at >= 128, Red at >= 160
  maxWords: 30,   // Shows word count: Amber at >= 24, Red at >= 30
}
```

---

### `textarea`

A multi-line text input. Use for descriptions, excerpts, or any plain text longer than a sentence.

```ts
{
  name: 'excerpt',
  type: 'textarea',
  admin: {
    placeholder: 'Short summary of the post...',
    description: 'Shown in list cards. Keep under 160 characters.',
  }
}
```

- **Stored as:** `TEXT` (SQL) / `string` (MongoDB)
- **API returns:** `string`
- **Admin UI:** `<textarea />` (auto-expanding)

---

### `richText`

A full block-based rich text editor powered by **Tiptap**. Supports headings, lists, quotes, code blocks, inline formatting, and embedded media.

```ts
{
  name: 'body',
  type: 'richText',
}
```

- **Stored as:** `JSONB` (PostgreSQL) / `JSON` column (MySQL) / subdocument (MongoDB)
- **API returns:** A Tiptap/ProseMirror JSON document object
- **Admin UI:** Tiptap editor with a floating toolbar

> **Note:** Rich text is not a plain HTML string. Use a Tiptap renderer on your frontend to convert the JSON to HTML, or use `@tiptap/html` to do it server-side.

---

### `email`

A text input that validates the value is a correctly formatted email address.

```ts
{
  name: 'contactEmail',
  type: 'email',
  required: true,
}
```

- **Validation:** RFC 5322 format check (server + client)
- **Stored as:** `VARCHAR` / `string`
- **API returns:** `string`
- **Admin UI:** `<input type="email" />`

---

### `icon`

A searchable icon picker backed by the [Lucide](https://lucide.dev) icon library. Stores the selected icon name as a plain string.

```ts
{
  name: 'featureIcon',
  type: 'icon',
  label: 'Feature Icon',
  admin: {
    description: 'Choose an icon to represent this feature.',
  }
}
```

- **Stored as:** `VARCHAR` / `string` — the Lucide component name, e.g. `"Rocket"`, `"ShieldCheck"`
- **API returns:** `string`
- **Admin UI:** A popover button opening a categorized and searchable grid of all Lucide icons. Includes category-based filtering tabs and paginated "Load more" behavior for lag-free scrolling. The selected icon is previewed beside the button.

#### Rendering on the frontend (Vue / Nuxt)

```vue
<script setup>
import * as LucideIcons from 'lucide-vue-next'
const props = defineProps(['iconName'])
const Icon = LucideIcons[props.iconName]
</script>

<template>
  <component :is="Icon" v-if="Icon" class="w-5 h-5" />
</template>
```

#### Rendering on the frontend (React / Next.js)

```tsx
import * as LucideIcons from 'lucide-react'

export function DynamicIcon({ name }: { name: string }) {
  const Icon = (LucideIcons as any)[name]
  return Icon ? <Icon className="w-5 h-5" /> : null
}
```

### `url`

A link picker that supports both external URLs and internal links to any collection document. The Admin UI renders a two-tab interface — **Internal Link** and **External Link**.

```ts
{
  name: 'ctaLink',
  type: 'url',
}
```

#### Stored shape

The field always stores an object, never a bare string:

```ts
// External link
{
  type: 'custom',
  url: 'https://example.com',
  label: 'Learn More',        // optional
}

// Internal link (collection document)
{
  type: 'internal',
  url: '/blog/my-post',       // resolved frontend URL (requires urlPattern on the collection)
  relationTo: 'blog',         // collection slug
  value: 'doc-id-abc123',     // document ID
  label: 'Read the post',     // optional
}
```

- **Stored as:** `JSONB` / `object`
- **API returns:** object as above
- **Admin UI:** Two-tab picker — External (URL input) or Internal (collection + document search)

#### Using the value on the frontend

For external links, use `url` directly. For internal links, use the pre-resolved `url` when a `urlPattern` is configured on the target collection, or fall back to fetching the document by `relationTo` + `value` if it isn't:

```ts
function resolveLink(link: { type: string; url?: string; relationTo?: string; value?: string }) {
  if (!link) return null
  if (link.type === 'custom') return link.url
  // type === 'internal': url is pre-resolved if urlPattern was set on the collection
  return link.url ?? null
}
```

#### Resolving internal link URLs with `urlPattern`

By default, internal links store `url: undefined` unless the target collection defines a `urlPattern`. Add `urlPattern` to the collection's `admin` config using `{fieldName}` placeholders — the Admin UI will interpolate the selected document's fields into the pattern at save time:

```ts
defineCollection({
  slug: 'blog',
  admin: {
    urlPattern: '/blog/{slug}',   // e.g. /blog/my-post
  },
  fields: [
    { name: 'title', type: 'text' },
    { name: 'slug',  type: 'text' },
  ],
})
```

```ts
defineCollection({
  slug: 'pages',
  admin: {
    urlPattern: '/{slug}',        // e.g. /about
  },
  fields: [...],
})
```

With `urlPattern` set, any URL field pointing to that collection will store a usable `url` string — no extra API call needed on the frontend.

> [!NOTE]
> `urlPattern` is purely a frontend convenience. It does not affect how documents are stored or served by the API.

## Numeric & Boolean

### `number`

An integer or floating-point number input.

```ts
{
  name: 'price',
  type: 'number',
  required: true,
  defaultValue: 0,
}
```

- **Stored as:** `NUMERIC` / `FLOAT` / `number`
- **API returns:** `number`
- **Admin UI:** `<input type="number" />` with step controls

---

### `boolean`

A true/false toggle.

```ts
{
  name: 'featured',
  type: 'boolean',
  defaultValue: false,
  admin: {
    description: 'Show this post in the featured section on the homepage.',
  }
}
```

- **Stored as:** `BOOLEAN` / `boolean`
- **API returns:** `boolean`
- **Admin UI:** Toggle switch

## Date & Time

### `date`

A calendar date picker.

```ts
{
  name: 'publishDate',
  type: 'date',
}
```

- **Stored as:** `DATE` (SQL) / `string` (MongoDB)
- **API returns:** ISO date string (YYYY-MM-DD), e.g. `"2024-06-01"`
- **Admin UI:** Popover calendar date picker

---

### `datetime`

A date and time picker. Values are stored as ISO-8601 strings.

```ts
{
  name: 'publishedAt',
  type: 'datetime',
}
```

- **Stored as:** `TIMESTAMPTZ` (PostgreSQL) / `DATETIME` (MySQL) / `string` (MongoDB)
- **API returns:** ISO-8601 string, e.g. `"2024-06-01T10:00:00.000Z"`
- **Admin UI:** Calendar date picker with hours and minutes time selectors

---

### `daterange`

A date range picker for picking start and end dates.

```ts
{
  name: 'eventRange',
  type: 'daterange',
}
```

- **Stored as:** `JSON` (SQL) / `object` (MongoDB)
- **API returns:** An object with optional `from` and `to` properties: `{ from?: string, to?: string }`
- **Admin UI:** Popover interactive range calendar

---

### `time`

A time-only picker.

```ts
{
  name: 'openingTime',
  type: 'time',
}
```

- **Stored as:** `TIME` / `VARCHAR` (SQL) / `string` (MongoDB)
- **API returns:** Time string (HH:MM), e.g. `"14:30"`
- **Admin UI:** Clock-based time dropdowns for hour and minute select

## Selection Fields

### `select`

A single-value dropdown. Options must be defined in the field config.

```ts
{
  name: 'status',
  type: 'select',
  defaultValue: 'draft',
  options: [
    { label: 'Draft', value: 'draft' },
    { label: 'Published', value: 'published' },
    { label: 'Archived', value: 'archived' },
  ],
}
```

Options can also be a plain string array — Dyrected will convert `'draft'` to `{ label: 'Draft', value: 'draft' }` automatically.

Options can also be **dynamically resolved** at request time — from a database query, an external API, or a client-side hook that reacts to other field values. See [Dynamic Options](/docs/concepts/dynamic-options) for all three approaches.

- **Stored as:** `VARCHAR` / `string`
- **API returns:** The selected `value` string
- **Admin UI:** Dropdown `<Select />` with an inline click-to-clear button (X) when a value is selected

#### Radio layout

For 2–5 options where you want all choices visible at once, set `admin.layout: 'radio'`:

```ts
{
  name: 'status',
  type: 'select',
  options: [
    { label: 'Draft',     value: 'draft' },
    { label: 'Published', value: 'published' },
    { label: 'Archived',  value: 'archived' },
  ],
  admin: {
    layout: 'radio',
    direction: 'horizontal', // or 'vertical' (default)
  }
}
```

- `direction: 'horizontal'` — radio buttons in a wrapping row.
- `direction: 'vertical'` — stacked column (default).
- Stored and returned identically to a standard `select`.

---

### `multiSelect`

Like `select` but allows the user to pick multiple values. Stored as an array.

```ts
{
  name: 'tags',
  type: 'multiSelect',
  options: ['technology', 'design', 'business', 'lifestyle'],
}
```

Like `select`, `multiSelect` also supports dynamic server-side resolvers and client-side hooks. See [Dynamic Options](/docs/concepts/dynamic-options).

- **Stored as:** `JSON` array / `TEXT[]` (PostgreSQL)
- **API returns:** `string[]`
- **Admin UI:** Tag-based multi-select with search and an inline click-to-clear button (X) when one or more values are selected

---

## Relationship Fields

### `relationship`

Links a field to documents in another collection. The value stored is the related document's `id`. When fetching with `depth >= 1`, the full related document is returned inline.

```ts
{
  name: 'author',
  type: 'relationship',
  relationTo: 'users',   // slug of the target collection
  required: true,
}
```

**Multi-relationship** (stores an array of IDs):

```ts
{
  name: 'categories',
  type: 'relationship',
  relationTo: 'categories',
  // value will be string[] when populated from the admin
}
```

- **Stored as:** `VARCHAR` (single) / `JSON` array (multi)
- **API returns (depth=0):** `string` or `string[]` — the raw ID(s)
- **API returns (depth=1+):** The full related document object (or array of objects)
- **Admin UI:** Searchable combobox. For upload collections, shows a thumbnail grid picker instead.

#### Depth

Control how deeply relationships are resolved via the `depth` query parameter:

```
GET /api/collections/posts?depth=1      // populate one level
GET /api/collections/posts/abc?depth=2  // populate nested relationships too
```

> **Tip:** Set `depth=0` when you only need IDs (e.g. for a sidebar count), and `depth=1` when you need to display related data.

---

### `join`

A virtual read-only field that shows documents from another collection that reference the current document. No data is stored on this side — the relationship lives on the related document's `relationship` field.

```ts
{
  type: 'join',
  label: 'Comments',
  collection: 'comments',  // target collection slug
  on: 'post',              // the relationship field on the target collection
}
```

- **Stored as:** Nothing — this is a virtual field; no column is created
- **API returns:** Nothing — join fields are UI-only and are not included in API responses
- **Admin UI:** A read-only list of linked documents with links to their edit pages. Includes a "Create new" button that pre-fills the relationship field pointing back to the current document.

> **Note:** The `join` field has no `name` property and does not contribute to the document's data shape. If the current document has not been saved yet, the join panel will prompt you to save first.

## Structural Fields

### `object`

Groups related fields into a nested object. Does **not** create a new database table — the grouped data is stored as a JSON column inline.

```ts
{
  name: 'seo',
  type: 'object',
  fields: [
    { name: 'metaTitle', type: 'text' },
    { name: 'metaDescription', type: 'textarea' },
    { name: 'ogImage', type: 'relationship', relationTo: 'media' },
  ],
}
```

- **API returns:** `{ metaTitle: string, metaDescription: string, ogImage: string | object }`
- **Admin UI:** Collapsible group panel with a distinct border

---

### `array`

A list of repeating field groups. Each item in the array has the same sub-field shape.

```ts
{
  name: 'faq',
  type: 'array',
  fields: [
    { name: 'question', type: 'text', required: true },
    { name: 'answer', type: 'textarea', required: true },
  ],
}
```

- **Stored as:** `JSON` / `JSONB`
- **API returns:** `Array<{ question: string, answer: string }>`
- **Admin UI:** Repeatable card list with Add/Remove buttons and drag-to-reorder. Prompts the editor with a safety confirmation dialog before deletion to prevent accidental data loss.

---

### `blocks`

A flexible layout builder. Each block in the list can be a different type, chosen from a predefined set of `Block` definitions. Ideal for page builders and rich landing pages.

```ts
{
  name: 'pageContent',
  type: 'blocks',
  blocks: [
    {
      slug: 'hero',
      labels: { singular: 'Hero', plural: 'Heroes' },
      fields: [
        { name: 'heading', type: 'text', required: true },
        { name: 'subheading', type: 'textarea' },
        { name: 'backgroundImage', type: 'relationship', relationTo: 'media' },
      ],
    },
    {
      slug: 'richTextBlock',
      labels: { singular: 'Rich Text', plural: 'Rich Text Blocks' },
      fields: [
        { name: 'content', type: 'richText' },
      ],
    },
    {
      slug: 'callToAction',
      labels: { singular: 'Call to Action', plural: 'Calls to Action' },
      fields: [
        { name: 'text', type: 'text' },
        { name: 'link', type: 'url' },
        { name: 'variant', type: 'select', options: ['primary', 'secondary', 'ghost'] },
      ],
    },
  ],
}
```

- **Stored as:** `JSON` / `JSONB`
- **API returns:** `Array<{ blockType: string, ...blockFields }>`. Each item includes a `blockType` property matching the block's `slug`.
- **Admin UI:** Block-picker modal + per-block inline editor. Prompts the editor with a safety confirmation dialog before deletion to prevent accidental data loss.

---

### `json`

A raw JSON editor for arbitrary structured data. Use when no other field type fits. Avoid if you can model the shape explicitly with `object` or `array`.

```ts
{
  name: 'metadata',
  type: 'json',
}
```

- **Stored as:** `JSONB` / `JSON`
- **API returns:** The raw parsed JSON value
- **Admin UI:** Code editor with JSON syntax highlighting and validation

---

## Layout Fields

### `row`

A virtual layout-only field that arranges its children side-by-side in a horizontal row. No database column is created; children write their values at the top-level document path as if the `row` wrapper didn't exist.

```ts
{
  type: 'row',
  fields: [
    { name: 'firstName', type: 'text', admin: { width: '50%' } },
    { name: 'lastName',  type: 'text', admin: { width: '50%' } },
  ],
}
```

- **Stored as:** Nothing — `row` is layout-only; each child field stores its own value normally
- **API returns:** Nothing for the row itself — children appear at the parent level as usual
- **Admin UI:** Children are rendered in a flex-wrap row. Each child's width is controlled by `admin.width` (any CSS value). Children without a `width` grow equally to fill the remaining space.

> **Note:** `row` does not require a `name` property. Since it produces no database column, naming it is optional and unused.

## Admin Field Options

The `admin` object on a field controls how it behaves in the Admin UI. None of these affect the API or database.

```ts
{
  name: 'internalNotes',
  type: 'textarea',
  admin: {
    placeholder: 'Add internal notes here...',
    description: 'Only visible to admins. Never shown to end users.',
    readOnly: false,
    hidden: false,
    condition: (data) => data.status === 'published',
    tab: 'Advanced',
  }
}
```

| Property | Type | Applies to | Description |
|---|---|---|---|
| `placeholder` | `string` | `text`, `textarea`, `url`, `email` | Input placeholder text. |
| `description` | `string` | All | Help text rendered below the field. |
| `readOnly` | `boolean` | All | Renders the field as disabled. The value is still submitted. |
| `hidden` | `boolean` | All | Hides the field from the form entirely. The value is preserved in the database. |
| `condition` | `(data: any) => boolean` | All | A function that receives the current document values and returns `true` to show the field, `false` to hide it. Evaluated reactively as the editor types. |
| `tab` | `string` | All | Assigns the field to a named tab. When any field in a collection has a `tab`, the form renders a tab bar. Fields without a `tab` are placed in a "General" tab. |
| `layout` | `'radio'` | `select` | Renders the select as radio buttons instead of a dropdown. Recommended for 2–5 options. |
| `direction` | `'horizontal' \| 'vertical'` | `select` (radio layout) | Controls the orientation of radio buttons. Defaults to `'vertical'`. |
| `width` | `string` | Fields inside a `row` | CSS width of the field within its row container (e.g. `'50%'`, `'200px'`). Fields without a `width` grow equally. |

### Tabs layout

When at least one field in a collection has `admin.tab` set, the entire form switches to a tabbed layout. You can mix tabbed and un-tabbed fields freely — un-tabbed fields are automatically grouped under a **General** tab.

```ts
fields: [
  { name: 'title',       type: 'text' },                              // → General tab
  { name: 'body',        type: 'richText' },                          // → General tab
  { name: 'metaTitle',   type: 'text',     admin: { tab: 'SEO' } },
  { name: 'metaDesc',    type: 'textarea', admin: { tab: 'SEO' } },
  { name: 'publishedAt', type: 'date',     admin: { tab: 'Publishing' } },
  { name: 'status',      type: 'select',   options: ['draft', 'published'], admin: { tab: 'Publishing' } },
]
```

### Custom admin input components

You can replace the default input for any field with your own React component using `admin.component`:

```ts
{
  name: 'color',
  type: 'text',
  admin: {
    component: ColorPickerInput,
  }
}
```

The component receives a standard set of props:

| Prop | Type | Description |
|---|---|---|
| `value` | `any` | The current field value from the form state. |
| `onChange` | `(value: any) => void` | Call this to update the field value. |
| `field` | `FieldSchema` | The full field definition from the collection config. |
| `readOnly` | `boolean` | Whether the field should be rendered as non-editable. |

```tsx
// Example: a simple hex color picker
export function ColorPickerInput({ value, onChange, readOnly }: AdminInputProps) {
  return (
    <input
      type="color"
      value={value || '#000000'}
      onChange={(e) => onChange(e.target.value)}
      disabled={readOnly}
      className="h-10 w-20 cursor-pointer rounded border border-input"
    />
  )
}
```

Custom components are purely presentational — validation, default values, and `required`/`unique` constraints all continue to work based on the field definition.

## Field Access

Field-level access control limits who can read or write individual fields.

```ts
{
  name: 'internalNotes',
  type: 'textarea',
  access: {
    read:   ({ user }) => user?.role === 'admin',
    update: ({ user }) => user?.role === 'admin',
  }
}
```

- **`read`**: If it returns `false`, the field is **stripped from the API response** for that user. The Admin UI also hides the field from the form.
- **`update`**: If it returns `false`, the field value is **silently ignored** on write. The Admin UI renders the field as read-only.

Both functions receive `{ user, doc, data, req }` — the same shape as collection-level access functions.

## Field Hooks

Field hooks allow transformation or async logic at the field level, without writing a full collection hook.

```ts
{
  name: 'email',
  type: 'email',
  hooks: {
    beforeChange: [
      ({ value }) => value.toLowerCase().trim(),
    ],
    afterRead: [
      ({ value }) => value, // can mask, format, etc.
    ],
  }
}
```

| Hook | When it runs | Return value |
|---|---|---|
| `beforeChange` | Before the document is saved | The transformed value to persist |
| `afterRead` | After the document is fetched | The transformed value to return |

Hook functions receive `{ value, originalDoc, data, user }`.
