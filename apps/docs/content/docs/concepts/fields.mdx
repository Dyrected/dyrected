---
title: Fields
description: How fields define the shape of your content — the types available and the properties they share.
---

A field is the basic unit of content in Dyrected. Every collection and global is made up of fields, and together they define both the database schema and the Admin UI form.

```ts
defineCollection({
  slug: 'posts',
  fields: [
    { name: 'title',     type: 'text',         required: true },
    { name: 'body',      type: 'richText' },
    { name: 'status',    type: 'select',        options: ['draft', 'published'], defaultValue: 'draft' },
    { name: 'author',    type: 'relationship',  relationTo: 'users' },
    { name: 'publishedAt', type: 'datetime' },
  ],
})
```

---

## Available field types

| Category | Types |
|---|---|
| Text | `text`, `textarea`, `richText`, `email`, `url`, `icon` |
| Number & boolean | `number`, `boolean` |
| Date & time | `date`, `datetime`, `time` |
| Selection | `select`, `multiSelect`, `radio` |
| Relationships | `relationship`, `join` |
| Structural | `object`, `array`, `blocks`, `json` |
| Layout | `row` |

---

## Every field shares these base properties

```ts
{
  name: 'myField',          // key in the database and JSON response
  type: 'text',             // field type (see table above)
  label: 'My Field',        // Admin UI label (defaults to title-cased name)
  required: false,          // enforced client and server-side
  unique: false,            // database-level unique constraint
  defaultValue: undefined,  // initial value for new documents
  admin: { ... },           // UI-only options (placeholder, description, hidden, condition, tab...)
  access: { read, update }, // field-level access control
  hooks: { beforeChange, afterRead }, // field-level lifecycle hooks
}
```

For a complete description of every field type and its options, see the [Field Types Reference](/docs/reference/fields).

---

## Fields are the schema

When Dyrected syncs the schema (on startup for self-hosted projects, or via `npx @dyrected/cli sync:schema` for Cloud), it uses your field definitions to create or update database columns. Changing a field type is a migration — see [Schema concepts](/docs/concepts/schema) for how lazy migrations work.
