---
title: Access Control
description: Collection and field-level access control using JavaScript functions or Jexl expression strings.
---

Dyrected uses a rule-based access control system. Every collection and field defines its own rules as either a JavaScript function or a Jexl expression string — there is no global role registry or permission table.

---

## How Access Works

Access functions are called on every request **before** any database operation. They receive the current user (from the JWT on the request) plus context, and return:

- `true` — allow the operation
- `false` — deny (returns `403 Forbidden`)
- `object` — allow, but filter the results to only documents matching the object (used for row-level security)

```ts
type AccessFunction = (args: {
  user: AuthenticatedUser | null
  doc?: Record<string, any>    // the existing document (on read/update/delete)
  data?: Record<string, any>   // the incoming data (on create/update)
  req: HonoRequest
}) => boolean | object | Promise<boolean | object>
```

## Collection-Level Access

Define access rules on the `access` key of a `CollectionConfig`:

```ts
export const Posts = defineCollection({
  slug: 'posts',
  access: {
    read:   ({ user, doc }) => doc?.status === 'published' || !!user,
    create: ({ user }) => ['editor', 'admin'].includes(user?.role),
    update: ({ user, doc }) => user?.id === doc?.authorId || user?.role === 'admin',
    delete: ({ user }) => user?.role === 'admin',
  },
  fields: [...],
})
```

| Operation | HTTP Method | Access Key |
|---|---|---|
| List & get single | `GET` | `read` |
| Create | `POST` | `create` |
| Update | `PATCH` | `update` |
| Delete | `DELETE` | `delete` |

### Public Access

```ts
access: {
  read:   () => true,   // anyone can read
  create: () => true,   // anyone can submit (e.g. a contact form)
  update: () => false,  // nobody can update
  delete: () => false,
}
```

### Row-Level Filtering

When `read` returns an **object**, Dyrected treats it as a `where` clause and automatically filters the query:

```ts
access: {
  // Users can only read their own orders
  read: ({ user }) => {
    if (!user) return false
    if (user.role === 'admin') return true
    return { customer: user.id }   // adds WHERE customer = user.id
  }
}
```

The filter object uses the same shape as the `where` query parameter on the API.

### Async Access

Access functions can be `async` — useful for lookups:

```ts
access: {
  update: async ({ user, doc }) => {
    const org = await db.findOne({ collection: 'orgs', id: doc.orgId })
    return org?.members.includes(user?.id)
  }
}
```

## Field-Level Access

Fields can define their own `access` object. This is evaluated **after** collection-level access is granted.

```ts
{
  name: 'internalNotes',
  type: 'textarea',
  access: {
    read:   ({ user }) => user?.role === 'admin',
    update: ({ user }) => user?.role === 'admin',
  }
}
```

| Key | Effect on reads | Effect on writes |
|---|---|---|
| `read: () => false` | Field is **stripped from the response** | — |
| `update: () => false` | — | Field is **silently ignored** on write |

Field access functions receive the same `{ user, doc, data, req }` args as collection access.

**Admin UI behaviour:**
- Fields where `read` returns `false` are hidden from the edit form.
- Fields where `update` returns `false` are rendered as read-only in the form.

---

## Global-Level Access

Globals support `read` and `update`:

```ts
export const SiteSettings = defineGlobal({
  slug: 'site-settings',
  access: {
    read:   () => true,
    update: ({ user }) => user?.role === 'admin',
  },
  fields: [...],
})
```

## Functions vs Jexl strings

Each access key accepts either a **JavaScript function** or a **Jexl expression string**. Both are evaluated server-side on every request.

```ts
access: {
  // Function — full JS, async-capable, can return a where filter
  update: ({ user, doc }) => user?.role === 'admin' || user?.id === doc?.authorId,

  // Jexl string — serialisable, storable in a database, works in Cloud schemas
  delete: "user.role == 'admin'",
}
```

| | Function | Jexl string |
|---|---|---|
| Async / DB lookups | Yes | No |
| Row-level `where` filter | Yes (return an object) | No |
| Serialisable / Cloud-compatible | No | Yes |
| TypeScript autocomplete | Yes | No |

Use functions when you need async lookups or row-level filtering. Use Jexl strings when your access rules need to be stored or synced to Dyrected Cloud. Simple boolean checks work equally well as either.

## Common Patterns

### Blog: public reads, staff writes, authors own their content

Published posts are readable by anyone. Only logged-in users can create. Authors can edit their own posts; admins can edit anything. Only admins can delete.

```ts
// Function form — use when you need the doc value or async logic
export const Posts = defineCollection({
  slug: 'posts',
  access: {
    read:   ({ user, doc }) => doc?.status === 'published' || !!user,
    create: ({ user }) => !!user,
    update: ({ user, doc }) => user?.role === 'admin' || user?.id === doc?.authorId,
    delete: ({ user }) => user?.role === 'admin',
  },
  fields: [...],
})

// Jexl string form — use for simple role checks or Cloud-synced schemas
export const Posts = defineCollection({
  slug: 'posts',
  access: {
    read:   "doc.status == 'published' || user != null",
    create: 'user != null',
    update: "user.role == 'admin' || user.id == doc.authorId",
    delete: "user.role == 'admin'",
  },
  fields: [...],
})
```

To hide the `status` field from authors so they cannot self-publish, combine this with field-level access:

```ts
{
  name: 'status',
  type: 'select',
  options: ['draft', 'published'],
  access: {
    update: ({ user }) => user?.role === 'admin' || user?.role === 'editor',
  },
}
```

### Contact form / lead capture: public submit, staff reads only

Anyone on the internet can submit the form. Only authenticated staff can read the submissions. Nobody can edit or delete entries after submission.

```ts
export const Inquiries = defineCollection({
  slug: 'inquiries',
  access: {
    create: () => true,
    read:   ({ user }) => !!user,
    update: () => false,
    delete: ({ user }) => user?.role === 'admin',
  },
  fields: [
    { name: 'name',    type: 'text',  required: true },
    { name: 'email',   type: 'email', required: true },
    { name: 'message', type: 'textarea' },
  ],
})
```

---

### E-commerce orders: users see their own, admins see all

`read` returning an object is treated as a `where` filter — so regular users automatically get a filtered list without any extra code in the API route.

```ts
export const Orders = defineCollection({
  slug: 'orders',
  access: {
    read: ({ user }) => {
      if (!user) return false
      if (user.role === 'admin') return true
      return { customer: { equals: user.id } }  // row-level filter
    },
    create: ({ user }) => !!user,
    update: ({ user }) => user?.role === 'admin',
    delete: ({ user }) => user?.role === 'admin',
  },
  fields: [...],
})
```

### Role-based team: admin / editor / viewer

A three-tier role model. Viewers can read. Editors can read and write. Only admins can delete.

```ts
// Function form — extract helpers so the rule isn't copy-pasted across collections
const isEditor   = ({ user }: AccessArgs) => ['admin', 'editor'].includes(user?.role)
const isAdmin    = ({ user }: AccessArgs) => user?.role === 'admin'
const isLoggedIn = ({ user }: AccessArgs) => !!user

export const Articles = defineCollection({
  slug: 'articles',
  access: {
    read:   isLoggedIn,
    create: isEditor,
    update: isEditor,
    delete: isAdmin,
  },
  fields: [...],
})

// Jexl string form
export const Articles = defineCollection({
  slug: 'articles',
  access: {
    read:   'user != null',
    create: "user.role == 'admin' || user.role == 'editor'",
    update: "user.role == 'admin' || user.role == 'editor'",
    delete: "user.role == 'admin'",
  },
  fields: [...],
})
```

### Invite-only community: restrict create to admins

Public reads, but only admins can create new members. Users can update their own profile. No one can delete via the API.

```ts
export const Members = defineCollection({
  slug: 'members',
  auth: true,
  access: {
    read:   () => true,
    create: ({ user }) => user?.role === 'admin',
    update: ({ user, doc }) => user?.role === 'admin' || user?.id === doc?.id,
    delete: () => false,
  },
  fields: [...],
})
```
