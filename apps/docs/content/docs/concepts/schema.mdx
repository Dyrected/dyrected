In Dyrected, your content model is defined as a series of **Collections** and **Globals** in your `dyrected.config.ts`.

## Collections

Collections are used for content that has multiple entries, like blog posts, products, or users.

```typescript
export default defineConfig({
  collections: [
    {
      slug: 'posts',
      labels: {
        singular: 'Post',
        plural: 'Posts',
      },
      fields: [
        { name: 'title', type: 'text', required: true },
        { name: 'content', type: 'richText' },
      ],
    },
  ],
});
```

## Globals

Globals are used for "singleton" content that only has one instance, like site settings, navigation menus, or a home page hero section.

```typescript
export default defineConfig({
  globals: [
    {
      slug: 'settings',
      label: 'Site Settings',
      fields: [
        { name: 'siteName', type: 'text' },
        { name: 'logo', type: 'relationship', relationTo: 'media' },
      ],
    },
  ],
});
```

## Admin Customization

You can control how your collections appear in the Admin UI:

```typescript
{
  slug: 'posts',
  admin: {
    icon: 'Newspaper',
    useAsTitle: 'title',
    defaultColumns: ['title', 'createdAt'],
    group: 'Content',
    hidden: false
  }
}
```

`admin.icon` accepts only valid Lucide component names. Editors see it beside the collection or global in the Admin sidebar; invalid values from untyped clients safely fall back to the default icon.

## Seeding & Migrations

Dyrected provides built-in tools for managing data over time.

### `initialData` (Auto-Seeding)
You can provide an array of objects to automatically seed a collection or global when it is first created (or if it is empty).

```typescript
{
  slug: 'categories',
  initialData: [
    { name: 'News', slug: 'news' },
    { name: 'Events', slug: 'events' },
  ],
  fields: [...]
}
```

### `renameTo` (Lazy Migration)
If you rename a field, use `renameTo` to ensure old data is still readable under the new name.

```typescript
{
  name: 'fullName',
  type: 'text',
  renameTo: 'name', // Checks 'name' if 'fullName' is missing
}
```

### `promoted` (Performance)
By default, Dyrected stores data in a JSON blob. This is great for flexibility, but large collections can suffer if you frequently filter by non-indexed fields. For fields that need native SQL indexing, set `promoted: true`.

```typescript
{
  name: 'slug',
  type: 'text',
  unique: true,
  promoted: true, // Extracted to a real SQL column
}
```

**How it works:**
1. When you run `sync:schema` (or when the service starts), Dyrected inspects your configuration.
2. For every `promoted: true` field, it ensures a matching column exists in your SQL table (SQLite, Postgres, or MySQL).
3. Queries using that field will automatically use the native SQL column instead of the JSON path, enabling the database to use its indexes.

**Supported Types for Promotion:**
- `text` (VARCHAR/TEXT)
- `number` (INTEGER/FLOAT)
- `checkbox` (BOOLEAN)
- `date` (TIMESTAMP)

---

### `renameTo` (Lazy Migration)
Renaming fields in a live database is usually a nightmare. Dyrected handles this with "Lazy Migrations". If you rename a field in your config, add the `renameTo` property pointing to the old name.

```typescript
{
  name: 'fullName',
  type: 'text',
  renameTo: 'name', // Checks 'name' if 'fullName' is missing
}
```

**Lifecycle:**
- **Read**: When fetching data, if `fullName` is missing, Dyrected will look for `name`.
- **Write**: When you save the document, it will be saved under the new key (`fullName`). Over time, your data naturally migrates to the new schema as entries are updated.
